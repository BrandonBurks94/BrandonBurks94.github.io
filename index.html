Professional Self-Assessment

My Computer Science coursework and Capstone Project have increased my knowledge of developing software as a total system. When I entered the program I was interested in programming. As I am leaving the program, I now understand the relationship between the architecture of software, the use of data, algorithms for processing and organizing that data, methods of verifying correctness, ways to protect against unauthorized access or malicious attacks, ways of documenting software systems and ways of communicating with stakeholders within those systems.

As a result of that interest and education, my area of focus will be Backend and Full Stack Software Engineering, with an emphasis on secure services and database-backed applications.

My professional experience as a Software Engineer with Amazon Freight Tech has also helped me connect my coursework to real software delivery. In that role, I work within an engineering team, participate in sprint planning, communicate technical progress and blockers, and contribute to decisions that affect maintainability, reliability, and stakeholder needs. That experience has reinforced the value of collaboration, documentation, testing, and clear communication alongside technical implementation.

This area of focus is supported through the artifact "Travlr Getaways" which is a MEAN-stack application. It has a public travel site and an Angular-based administrative single-page application. An Express/Node.js API and MongoDB persistence support both the frontend and backend functionality. The artifacts presented here, were not disparate pieces of coursework. In addition to improving the overall quality of the artifact, I demonstrated improvement over three areas: software design and engineering, algorithms/data structures, and databases. Through this methodology I showed that I could assess an existing system for risks, create plans for enhancements, develop improvements, and validate results with empirical measurements.

The resulting improvements to "Travlr Getaways" provide concrete examples of professional growth. I enhanced the software's backend by applying layered configuration, middleware, validation, service, repository, and error handling. I made several significant design improvements to ensure strong authentication related practices such as: validating all required secret keys upon initialization, creating reusable JWT middleware, strengthening password hashing and ensuring sanitized error messages are returned to users. I created a new recommendation endpoint based upon tokenization, an inverted index, sets, filtering, weighted scoring and deterministic sorting to address a practical issue related to discovering trips. Additionally, I improved the quality of the database by creating normalized numeric fields, performing schema validation, providing timestamped values, indexing frequently accessed data and creating logical query repositories.

The enhancements shown above represent many valuable skills associated with working in backend and full stack positions including: API design, secure configuration, authentication, validation, automated testing, data modeling, search/recommendation logic, written technical communication, determining tradeoffs, preserving compatibility with existing user interfaces, selecting legacy code over rewriting an application to use new technology, focused testing where evidence is most clear, writing test suites that verify behavior across multiple areas of a system.

By the time I implemented the last set of enhancements to improve database quality, there existed 23 successfully tested cases within my test suite that spanned all areas of the design, algorithms and persistence behaviors of the system.

This portfolio provides me with a way to showcase myself as a developer that understands how to work across multiple tiers of a software stack while considering maintainability, reliability, security and value to stakeholders. The code reviews, artifact comparisons, enhancement narratives and test evidence presented here not only indicate what I built but why the changes were important.

Enhancement Narratives

Enhancement One: Software Design and Engineering

This enhancement refactored the backend into explicit layers for configuration, authentication middleware, validation, service logic, repository access, and centralized error handling. It also strengthened password handling with scrypt, added timing-safe comparison, validated required environment variables at startup, sanitized unexpected API errors, and introduced automated backend tests.

Layered Architecture Secure API Design 13 Passing Tests

This enhancement aligns with Course Outcomes 1, 4, and 5. The architecture and security trade-off decisions support collaborative decision making, while the layered backend refactor, automated backend tests, GitHub Actions quality gate, safer configuration, reusable JWT middleware, stronger password hashing, timing-safe verification, and sanitized error responses demonstrate well-founded engineering practices and a security mindset.

Enhancement Two: Algorithms and Data Structures

This enhancement added a trip recommendation endpoint at GET /api/trips/recommendations. The implementation normalizes query criteria, tokenizes searchable trip data, builds an inverted index with a Map and Sets, filters by budget and duration, scores ranked matches, and applies deterministic tie-breaking.

Inverted Index Weighted Ranking 19 Passing Tests

This enhancement aligns with Course Outcomes 2, 3, and 4. The narrative communicates the recommendation design, trade-offs, and test evidence clearly for a technical audience, while the implementation applies algorithmic principles through tokenization, inverted indexing, sets, constraint filtering, weighted scoring, and stable sorting. It also adds practical application value through an integrated recommendation endpoint.

Enhancement Three: Databases

This enhancement improved the MongoDB and Mongoose data model by deriving structured fields from display values, including priceAmount, durationNights, and searchText. It added schema validation, timestamps, uppercase trip-code normalization, a unique code index, a compound price-and-duration index, a text-search index, and repository prefiltering for recommendation criteria.

Schema Design Indexes and Validation 23 Passing Tests

This narrative aligns with Course Outcomes 4 and 5. It uses well-founded database practices through Mongoose schema design, validation, normalized stored fields, indexes, timestamps, and repository query logic, while also strengthening data integrity by rejecting malformed persistence values.
